# P2: unprivileged collector agent (`collector/agent`, binary `vigie-collector`)

Implements PRP-001 section 4 for the unprivileged process: wire contract and signing, batch
builder with the truncation order, RAM spool, backoff, time gate, urgent push, log/neighbor/lease
sources as pure parsers, config and key handling, dnsmasq drop-in scripts. `#![forbid(unsafe_code)]`
in the library and the binary. **Never run on the router.** The binary does run on the host (see
Results).

## Layout

| Path | What |
|---|---|
| `collector/agent/src/model.rs`, `json.rs` | Batch model, hand-written JSON writer (no serde). Constructors enforce the schema limits, so a hostile LAN string cannot make the server reject a whole batch |
| `sign.rs` | `HMAC-SHA256(key, collector_id\|key_id\|boot_id\|seq\|sent_ts\|batch_id\|hex(SHA256(body)))` |
| `builder.rs` | Fits a window into 256 KiB, PRP truncation order, `truncated{kind:count}` |
| `spool.rs`, `backoff.rs`, `timegate.rs`, `urgent.rs`, `sender.rs` | RAM spool, backoff, time gate, urgent push policy, send engine behind a `Transport` trait |
| `neigh.rs`, `leases.rs`, `dnsmasq.rs`, `tail.rs`, `sightings.rs` | Pure parsers; log tail with cursor and rotation; mDNS/SSDP via the reviewed `vigie-parse` crate |

## Wire contract decisions

- **`sent_ts` is stamped per attempt**, and it is inside the signed body, so a spooled batch is kept
  as bytes up to `"sent_ts":` and finished (`sent_ts`, `dropped_batches`, `}`) and re-signed at each
  send. `batch_id` and `seq` are fixed at build time; retries are therefore recognised as duplicates
  by the server before its `sent_ts` check.
- `batch_id` is a lowercase UUIDv7 (the server rejects anything else). `boot_id` is random per
  process start (a restart resets `seq`, which the server allows for a new `boot_id`).
- Counters are clamped to int64 max and epoch seconds to 2^40 (schema limits).

## Truncation order: how it was read

The PRP says "leases/neigh/mDNS first; then DNS; then conntrack top-N by bytes, remainder folded".
This is implemented as a **retention priority** (the order budget is filled), so a flood of the bulkiest
data cannot evict the small identity records that re-attach a rolled MAC:

1. Identity group (leases, neigh, sightings), capped at 96 KiB so a lease/mDNS flood cannot starve the rest.
2. DNS, up to everything left minus conntrack's guaranteed share.
3. Conntrack: guaranteed `min(48 KiB, what it needs)`; top-N by bytes verbatim, the rest folded into
   one `other` bucket per MAC (bytes and flows conserved, tested).

Schema array caps (1000/2000/5000/5000/1000) are applied too, and everything dropped is counted in
`truncated`. If the PRP meant the opposite (drop leases/neigh/mDNS first), it is a one-line change in
`builder::build`; **please confirm the intended reading**.

## Clock jumps (no RTC)

The router clock can step by days when NTP syncs mid-window, and the server rejects a whole batch
(422, discarded by the engine) for a window over 24 h, `window_end` beyond `sent_ts + 300`, or any
`dns.ts` outside the window +-300 s. So:

- `window::WindowClock` derives `window_start` from the monotonic clock (`wall - (mono - last_flush)`),
  and a flush skipped by the time hold also restarts the window.
- `builder::build` clamps the window to 24 h and drops DNS rows outside window +-300 s, counting them
  as `truncated.dns_out_of_window`.
- Build date as a gate: OpenWrt's sysfixtime usually sets the boot clock from the newest file time in
  `/etc`, and installing the agent writes `/etc/vigie` after the build, so the build-date check will
  often pass on a stale clock. **The server `Date` check is the real gate**, and it is only exercised
  end to end once a transport parses response headers (`httpdate::parse_imf_fixdate` is ready).

## Assumed, not verified

- **dnsmasq DHCP log lines** (`requested options:`, `vendor class:`, `client provides name:`,
  `DHCPACK(...)`) and the `log-queries=extra` query/answer format are assumed from dnsmasq docs and the
  P0 sample fixture. P0 checklist items 2 and 3 are still open. Wrong formats make the parsers yield
  nothing (they never panic); the symptom is missing opt55/opt60 and `dns_log_quiet`.
- Two hedges written from memory of dnsmasq's source, also unverified: a long `requested options:` list
  may be split over several lines (the assembler accumulates, capped at 64), and scoped IPv6 clients
  may be logged as `fe80::1%br-lan/port` (the scope is stripped before the neighbor lookup).
- DNS queries are stamped with the **read time**, not the log time (log lines carry no year or zone).
- `procd_set_param user vigie` (procd taking the gid from the passwd entry), and `/etc/init.d/dnsmasq reload` on
  GL.iNet 4.8.3 are unverified.

## Security review fixes (second pass)

**DHCP serial collisions.** dnsmasq's per-transaction serial (xid) is chosen by the client, so it proves nothing
about which MAC a line belongs to. First pass tainted an entry when a second MAC showed up; the re-review showed
that MAC-less lines (INFORM and the option/vendor/name lines that follow it) still slip in. The current rule is in
"Re-review fixes" below (the log is a sequential stream; fingerprint lines attach only to the packet line right
before them).

**Root scripts in `/tmp`.** `vigie-dnsmasq-dropin.sh` and `vigie-log-watchdog.sh` run as root in world-writable
`/tmp`, so both source `vigie-lib.sh`, which refuses (exit 70, message on stderr) when a directory is a
symlink, not owned by the trusted uid (0), or group/other-writable, and when the log or drop-in is a symlink, not
a regular file or owned by an unexpected uid. Directories are created with `mkdir` under `umask 077` (fails on any
existing name, symlinks included), never `mkdir -p`; owner and mode are set only when that very `mkdir` succeeded
(see "Re-review fixes"); the log is created with
noclobber (`O_EXCL`); the drop-in is written to `mktemp` inside the verified directory and `mv`ed. Layout:
`/tmp/vigie` is `root:vigie 0751` (traverse-only for dnsmasq's run user), `dnsmasq.log` is `0640 root:vigie`,
`/tmp/dnsmasq.d` is `root 0755`, the key is `0600` owned by `vigie`. All `VIGIE_*` overrides are honoured only
with `VIGIE_TEST=1` (tests are not root); production ignores them and pins `PATH`.
**Assumption, not verified on the router:** dnsmasq opens its `log-facility` file as root before dropping
privileges and `fchown`s it to its run user while keeping the group (from dnsmasq's source), so the file stays
group-readable by `vigie`. That is why the log may be owned by uid 0 or by the uid dnsmasq runs as (see "Fourth review fixes"; `nobody` is no longer implied). Verify after the first
start with the checks in "Re-review fixes" (item 8). Also unverified:
busybox `stat -c %u/%a`, `mktemp` with a path template and `install` on GL.iNet (they work with the host busybox).

**Floods.** `Window` caps DNS rows (10,000 per window) and sightings (4,096 distinct), with a per-MAC DNS quota of
1,024 rows per window, so one chatty device cannot crowd out the others. The correlator caps pending queries per
client IP (256 between two polls) so a flood within one 2 s poll cannot evict other clients' queries, and counts
global evictions. Everything dropped is reported in the batch `truncated` map: `dns_quota_dropped`,
`dns_dropped`, `sightings_dropped`, `dns_pending_evicted`, `dns_client_throttled` (plus the builder's own keys: at
most 14 of the 16 the schema allows, including `tail_truncated` and `tail_bytes_skipped`; `TRUNCATED_RESERVE` is now 768 bytes, enough for all of them at int64 max).

**Clock before first contact.** Until a server `Date` has been seen, no data window is built. Rows are stamped with
monotonic seconds (`SyncState::stamp`), the window just accumulates (bounded), and each flush queues only an empty
probe batch: its reply, accepted or rejected (422 included), carries the `Date`. On the first `Date` the
provisional stamps are shifted to server time in one step (`Window::rebase_dns`, offset = server `Date` minus the monotonic second it arrived, never the local wall clock), so an NTP step of days before
first contact loses nothing and mis-times nothing. Urgent pushes are gated the same way. The server's 422 body is
only `{"error":"invalid_batch"}`, so staleness is judged locally: a 422 for a batch whose `window_end` is more than
24 h older than `sent_ts` is discarded as before, but counted in `Engine::dropped_stale`, reported to the server
through `dropped_batches` and logged (`Tick::DiscardedStale`). Limitation: the probe is only sent once the wall
clock passes the build date; a router stuck before it never makes contact (unchanged from the time gate).

**Key file.** `load_key` opens with `O_NOFOLLOW` (constants per architecture, taken from the `libc` crate sources:
0x8000 on arm/aarch64/powerpc, 0x20000 elsewhere; the aarch64 value was not exercised on hardware), then checks type,
mode and owner on the opened descriptor, and requires the parent directory to be a real directory, not
group/other-writable, owned by root or the agent. The key buffer and the engine's copy are overwritten after use
(best effort without `unsafe`).

**Smaller items.** The urgent-push table evicts the oldest MAC at 4,096 instead of switching itself off. On a
`duplicate:true` reply the retry's `dropped_batches` is not subtracted (the server ignored it), so the count is
reported again by the next batch. The xorshift RNG fallback is gone: `/dev/urandom` failure refuses startup (exit 71)
and skips building a batch (the data stays in the window); only retry jitter degrades to 0. A new-MAC urgent push
now refreshes the neighbor table immediately. **Neighbor lag:** the ip-to-MAC map is otherwise refreshed every 10 s,
so for up to ~10 s a device whose IP was re-leased to a different MAC can have its DNS queries attributed to the
previous holder of that IP (and queries from a brand-new device are dropped as unattributable); the immediate refresh
covers DHCP joins, not ARP/NDP-only changes. `transport::PinnedTransport::new(url, pins)` validates the https scheme
case-insensitively, rejects userinfo (also `%40` and backslash tricks), and requires at least one pin (strict base64
of 32 bytes, or the config file's lowercase hex); it is not a `Transport`, so `NoTransport` remains the only
implementation. `load()` runs it on the config, so a bad URL or pin fails startup and `--check`. `BATCH_CAP` (256 KiB) is
asserted to stay within the server body limit (`SERVER_MAX_BODY`, 512 KiB).

## Re-review fixes (third pass)

1. **DHCP xid poisoning (HIGH).** `DhcpAssembler` reads the log as a sequential stream. Packet lines
   (`DHCPREQUEST`/`DHCPDISCOVER`) open a context (xid + normalized MAC). `requested options:`, `vendor class:` and
   `client provides name:` attach only while that context is live, i.e. directly after the packet line (or after
   another attached line) with the same xid. Any other line ends the context: every other `DHCP*(` verb
   (`DHCPOFFER`, `DHCPACK`, and `DHCPINFORM`/`RELEASE`/`DECLINE`/`NAK`, which also taint the xid entry), DNS lines, a
   line with a different xid, and any line that did not parse (`break_context`, called from `main`). A second MAC
   on the xid taints it as before. Cost: an attacker can still make a victim's lease arrive without a fingerprint
   (denial of enrichment); it can no longer choose one. Each first `requested options:` of a context replaces the list
   (DISCOVER and REQUEST no longer concatenate), and a new DISCOVER for the same MAC resets opt55/opt60/name.
   Tests: `tests/review_dhcp_stream.rs` (reviewer's INFORM and between-REQUEST-and-ACK repros, other verbs, OFFER,
   interleaved MACs, legitimate xid reuse, DISCOVER reset). Not covered: an overlong line dropped by the tail
   does not break the context (dnsmasq never writes lines over 4 KiB, and the attacker cannot insert lines).
2. **Log truncate-and-refill (MED).** `parse_line` requires the exact prefix
   `<Mon> <d> hh:mm:ss dnsmasq[-dhcp][pid]: ` at the start of the line (no `contains`). The tail keeps the 64 bytes
   before its cursor and compares them on every poll; a shorter file or different bytes restart at offset 0 and drop
   the partial line, so a cursor that lands inside somebody's vendor class is never trusted (the reviewer's pad
   100/200/240 repro, plus a variant with a complete forged prefix, which only the fingerprint stops). Counted as
   `tail_truncated` (resets) and `tail_bytes_skipped` (overlong lines and discarded partial lines) in the batch
   `truncated` map. A reset replays the current file from 0 (duplicates are possible, nothing forged). The watchdog now
   rotates by rename (`dnsmasq.log` -> `.log.1`), creates a fresh `0640` file with the old owner and group `vigie`,
   and sends SIGUSR2 to dnsmasq (`pidof dnsmasq`; dnsmasq closes and reopens a file `log-facility`). In-place truncation
   remains only as an emergency when the log (or a `.1` dnsmasq never let go of) exceeds 2x the cap. Unverified on
   the router: that GL.iNet's dnsmasq reopens on SIGUSR2 and can write the fresh file (it is created with the previous
   file's owner so that it can).
3. **`ensure_dir`.** Owner and mode are set only when our own `mkdir` (no `-p`) created the leaf; an existing
   directory, or one that won the race, must already pass `require_dir` (root-owned, no group/other write, not a
   symlink) and is never chmod'ed or chown'ed by path. Every refusal also writes a `daemon.crit` line through
   `logger -t vigie`. Test: a `mkdir` stub that creates the attacker's directory and then fails.
4. **Fail closed on uid.** The init script returns 1 (and logs `vigie user missing`) unless `id -u vigie` succeeds,
   so procd can never fall back to root. `vigie-collector` reads the effective uid from `/proc/self/status` (no
   `unsafe`) and exits 77 for euid 0, or an unreadable status, unless `--allow-root` is passed (tests only; do not
   put it in the init script). The key-owner == euid check stays.
5. **uid.** `vigie-print-install-commands.sh` no longer creates `/tmp/vigie` (the root drop-in script does) and
   picks the first uid in 6700..6799 that is unused in `/etc/passwd` (gid = uid, unused in `/etc/group`); an explicit
   `VIGIE_UID` that is in use or outside the range is refused; it still only prints. The conntrack helper (separate
   branch) runs as root and creates a `0600` socket owned by the agent's uid; access is restricted by file ownership
   alone, so the printed commands tell the owner to pass the same uid to it as `--uid`.
6. **Rebase offset** now comes from `TimeGate::server_offset()` (server `Date` minus the monotonic second it was
   seen); `SyncState::observe` takes the gate, so the local wall clock cannot reach it. Test with a wall clock that
   is years off.
7. See item 1 (DISCOVER reset).
8. **Overrides and permissions.** `VIGIE_*` overrides in the root scripts (and `VIGIE_PASSWD`/`VIGIE_GROUP_FILE` in
   the print helper) are honoured only when `VIGIE_TEST=1`. `/tmp/vigie` is `root:vigie 0751` so dnsmasq's run user
   can traverse it, and the log is `0640 root:vigie`, created by the script before dnsmasq first opens it (dnsmasq
   is assumed to keep an existing file's group). **What to check on the router, in this order:**
   `ls -ln /tmp/vigie /tmp/vigie/dnsmasq.log` (directory `drwxr-x--x`, uid 0, group = the vigie gid; log
   `-rw-r-----`, group = the vigie gid, owner 0 or dnsmasq's uid), then restart dnsmasq and run
   `logread | grep dnsmasq | tail` (no "cannot open log file" / permission errors, and lines still arrive in
   `/tmp/vigie/dnsmasq.log`).
9. **Wiring tests** now live in `main.rs` (`#[cfg(test)]`): an unsynced `flush_window` queues exactly one empty
   probe and keeps its data; `push_identity` builds nothing until a server `Date` was seen. Both wiring mutants
   from the previous run (Probe early return, `allow_identity_push`) are killed.

## Fourth review fixes

1. **Prefix anchor test hole.** `strip_prefix` was already anchored; no test would have noticed an unanchored
   `split_once("dnsmasq-dhcp[")`, which forges a lease from `garbage Oct 20 14:00:00 dnsmasq-dhcp[1]: 9 DHCPACK(...)`.
   Tests now cover text before a valid prefix and a mid-line splice; that mutant is killed.
2. **`Tail::poll` no longer loses drained lines.** When the new file after a rotation (or a later read) fails, the lines
   already drained from the old file are returned and the failure is counted as `tail_open_failed` (a new `truncated`
   key, 15 of the 16 the schema allows; the cap sweeps include it). With nothing drained, the error is still returned.
   A partial line dropped on rotation is now counted in `tail_bytes_skipped`.
3. **euid refusal tested end to end.** `tests/review4_euid_bin.rs` runs the built binary under `unshare -Ur`: exit 77
   without `--allow-root` even with a bad config path, 78 with it, 78 as a normal user. Skipped with a printed reason
   when `unshare -Ur` is unavailable.
4. **Watchdog log ownership.** The new log is no longer a copy of the old owner. The uid dnsmasq runs as is read from
   `/proc/<pid>/status` (real and effective must agree); the new file is `uid:vigie 0640`. Uid 0 or an unresolved uid:
   nothing is rotated, `logger` warns, exit 70 (the emergency truncation above 2x the cap still runs). After SIGUSR2 the
   script waits up to 10 s; a still-empty new file while the old one kept growing is logged.
5. **Allowed owners** of `dnsmasq.log` and `.1` are root and the resolved dnsmasq uid only (`nobody` is not implied).
6. **Pid discovery** (`dnsmasq_pid` in `vigie-lib.sh`): the procd instance (`ubus call service list '{"name":"dnsmasq"}'`,
   parsed with grep), then `/var/run/dnsmasq/dnsmasq.*.pid`, then `pidof dnsmasq`. The first source with any hit
   decides; more than one distinct pid there is refused. Unverified on the router: the ubus output shape, the pidfile
   location and names, and that the busybox applets used (`grep -o`, `sort -u`, `test -k`) behave like the host's.
7. **`VIGIE_TEST` gate.** Refused as euid 0 when `/etc/init.d/vigie-collector` exists, unless the harness also sets
   `VIGIE_TEST_FORCE_ROOT=1`. The lib also refuses when `/tmp` lacks the sticky bit.
8. **procd respawn.** `respawn 3600 5 5` (5 retries) instead of unlimited. procd has no "gave up" hook, so the command
   is the wrapper `vigie-run.sh`, which counts exits 77/78 in `/var/run/vigie-collector/fails` (made by the init script,
   reset on each start) and logs once when the count reaches 5. Unverified: procd's exact retry off-by-one (the message may
   come one failure early or never), and that `/var/run` is writable by root at start on this firmware.
9. **Companion-line order is an assumption.** The assembler attaches `requested options:`, `vendor class:` and
   `client provides name:` lines to the preceding DHCPREQUEST/DISCOVER/ACK by their position in the log, assuming dnsmasq
   writes them in that order relative to those lines (from its docs, not from a capture). If real dnsmasq orders them
   differently, fingerprints (opt55/opt60/name) silently come out empty; leases are still produced. The P0 `logging-on.sh`
   run and a captured sample decide it. **Owner step:** capture roughly 30 lines around one DHCP exchange from the router's
   `logread` or `/tmp/vigie/dnsmasq.log`, mask the MACs and hostnames, and add it as a fixture.

## Findings that change the PRP

0. **Running as `nobody` shares the HMAC key with avahi**, which P0 shows also runs as `nobody`. The
   collector now runs as a dedicated `vigie` user and group (init template, key file owner,
   `/tmp/vigie` group), consistent with the conntrack helper, which refuses uid 65534.
   `deploy/vigie-print-install-commands.sh` prints the `/etc/passwd`, `/etc/group` and directory
   commands for the owner to review and run; nothing creates the user automatically.
1. **The unprivileged collector cannot rotate dnsmasq's log or signal it.** PRP section 4 says the
   collector renames the file and sends `SIGUSR2` to dnsmasq; as `nobody` it can do neither (dnsmasq is
   root's, `/tmp/vigie` is root's). The tail copes with rotation by anyone (rename + reopen, tested) and
   with in-place truncation, and `deploy/vigie-log-watchdog.sh` (root cron) bounds the file at 8 MB, but
   nothing rotates cleanly. Options: let the root watchdog rename + `SIGUSR2`, or accept truncation.
2. **The drop-in cannot be recreated by the collector** (it cannot write `/tmp/dnsmasq.d`). Recreation is
   `deploy/vigie-dnsmasq-dropin.sh ensure`, run by the init script at start and by root cron; the agent
   only verifies the file and raises `dns_log_quiet`.
3. **rustls needs a C cross compiler.** `rustls` with `ring` fails to build for aarch64-musl without one
   (`cc-rs: failed to find tool aarch64-linux-musl-gcc`); it builds with
   `CC_aarch64_unknown_linux_musl=clang CFLAGS_aarch64_unknown_linux_musl=--target=aarch64-unknown-linux-musl`.
   A probe binary that only builds a pinned-verifier `ClientConfig` is **769,608 bytes** (stripped,
   opt-level z, lto) on its own, so the agent would grow from ~490 KB to roughly 1.2 MB or more. RSS
   cost not measured. SPKI extraction also needs an X.509 DER parser (rustls does not expose SPKI hashing).

## Source wiring (branch feat/collector-wiring)

Conntrack helper client (`ctparse`, `ctfold`, `ctsock`), multicast listener (`mcast`, over the new
`net_spike` lib target: `sock`, `filter`, `recv`; net-spike still has its 50 tests, 14 lib + 36 bin) and
`wiring::Sources`, driven by `Agent::step` in `main.rs`. Two reader threads (`vigie-ct`, `vigie-mc`) behind
bounded channels (4 snapshots, 256 packets; a full queue drops the newest and counts it); the main loop only
`try_recv`s, at most 512 multicast packets per pass. `#![forbid(unsafe_code)]` kept.

- **Parser**: 1 MiB line cap (the helper allows 2 MiB; a table big enough for >1 MiB would be rejected every
  time and the helper cap should be lowered to match), 8192 records, nesting <= 8, control bytes/NUL, invalid
  UTF-8, duplicate or escaped keys, version != 1, trailing bytes all reject the whole snapshot. Counters
  saturate. Unknown fields skipped.
- **Socket checks** before every connect: parent directory not a symlink, owned by root or the agent, not
  group/other-writable; socket not a symlink, a socket, same owner rule, not group/other-writable. A path check is not atomic with
  `connect`; `UnixStream::peer_cred` is unstable in std, so a swap by root or the agent itself is accepted.
- **Hostile peers**: garbage, oversize, EOF mid-line, a line not finished within 10 s of its first byte: counted
  error, drop, reconnect with backoff 1 s doubling to 60 s (reset after a received snapshot). A silent
  connected peer is normal (it sends every interval); silence beyond 180 s counts as down.
- **Mapping**: `ip -> MAC` through the neighbor table (`IpAddr` normalised on both sides). Unmapped sources and the
  helper's `other_global` record are folded into `ct_unmapped_bytes`. Mapped `other` records become the MAC's
  `other` bucket. Bytes add across samples in a window, `flows` (a gauge per sample) takes the max.
- **Where conditions go**: the schema's `health` is closed (4 fields) and `truncated` is the only free-form slot
  (<= 16 keys, `[a-z_]{1,32}`). Used: `source_flags` bitmask (1 table_pressure, 2 acct_off, 4 conntrack socket
  down, 8 multicast bind failed), counters `ct_recounted`, `ct_dropped_keys`, `ct_errors` (reader errors + queue drops),
  `ct_unmapped_bytes`, `mcast_unmapped`, `mcast_dropped`; the per-device quota reuses `sightings_dropped`.
  `new_flows`, packets, `folded`, `evicted`, `skipped_lines` have no slot and are not reported. The builder now caps
  `truncated` at 16 keys (largest counts keep a key, the rest are summed into `truncated_other`, `source_flags`
  is exempt): without it the 15 existing keys plus these would make the server reject the whole batch.
- **Quotas**: sightings 64 distinct per MAC per window (new), 4096 per window (existing).
- **Shutdown**: std cannot install a signal handler without `unsafe`; SIGTERM takes the default action. State is RAM
  only by design, so nothing is lost that a clean stop would have saved.
- **Config**: new optional keys `conntrack_socket` (default `/tmp/vigie/conntrack.sock`), `lan_addr` (192.168.8.1),
  `lan_prefix` (24), `lan_iface` (br-lan).
- **Dependency**: the agent now depends on `socket2` through `net-spike` (SO_REUSEPORT and IP_MULTICAST_ALL cannot be set
  with std). Dev only: `vigie-conntrack` (tests drive the real helper serializer and `Publisher`), `socket2`.
- **Not verified**: anything on the router; the real helper protocol only against the helper's own library
  (round trip of `snapshot_json`, `bind_secure_with` + `Publisher`), not the running binary; IPv6 multicast was
  not exercised (needs an interface that accepts the join; `lan_iface` path untested); multicast tests need a
  non-loopback IPv4 route and skip with a message otherwise.

Mutation (hand-run, 59 single edits over parser, socket checks, line framing, backoff, fold, flags, staleness,
quotas, key cap, multicast): 5 survived the first run; 4 got tests (line cap +1, escaped keys, oversized line not
dropping the peer, uncounted multicast parse errors) and now die; the fifth was an equivalent no-op mutant.
Red-first evidence: the 16-key cap and the parser were run red (cap test failed with 25 keys; parser against a
