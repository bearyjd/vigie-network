## Product and completion criteria

A LAN-only inventory exposes stable device IDs, evidence and uncertainty, preserves
human labels, and supports human-approved identity changes. Enforcement belongs to
the separate control app. Unknown/ambiguous identities remain unassigned.

Code completion requires the identity APIs, known stitching fixes, end-to-end
identity tests, reproducible CI, accurate documentation, and independent adversarial
review of the final diff. Real-LAN acceptance separately requires router observations,
first real push, lease coverage and resource soak. Never claim those from fixtures.

## TDD seams

* API requests + real SQLite (in-process): catches authorization, stale decisions,
  transactional audit and retry errors; does not prove deployment permissions.
* Pipeline run/compute-apply + real SQLite (in-process): catches maturity, veto,
  rules and identity races; does not prove live router input formats.
* Existing collector-to-API TLS smoke (locally substitutable router inputs): catches
  wire/contract and service interaction faults; does not prove router coexistence.
* CLI/local gate (local subprocess): catches drift/build/regression failures;
  hosted status and real container/router acceptance require those environments.

Expected values come from contracts and worked fixtures. Run each new regression
red for its intended reason, implement minimally, then run relevant suites green.
Do not claim retroactive TDD for pre-existing code/tests.

full P2 classification accuracy are later milestones, not this code-completion claim.
